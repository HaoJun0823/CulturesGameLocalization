> 汉化方向：**德语 → 简体中文**，英语仅作辅助理解。
> 目标：高质量、语句通顺、**信、雅、达**；术语统一；每次改动可追溯（git + 术语词典）。
> 本指南为 v3，在 v2 基础上整合 `campaign_01_02` 换行修正的经验：段落合并的成因与**语义重分段**解法、正则作用域铁律、`.gitattributes` 强制 LF。

- **严禁改动** `eng` / `ger` 文本、`<languages>` 声明、文件头与结构标签。

## 2. 核心原则

1. **德语为主、英语为辅**：以 `<text lang="ger">` 为准；仅当德语歧义时用 `eng` 辅助。
2. **绝不使用 GAME_2/3/4/5 的波兰语/其他语言译文作来源**（质量差、不统一）。其同 ID 地图仅可在**理解上下文**时参考，译文不得照搬。
3. **术语统一**：专有名词先查 `language_union.csv`；新术语翻译后**必须追加**。
4. **信雅达**：
   - 信：忠于原意，不漏译、不增译、不曲解。
   - 达：符合中文表达习惯；任务句用自然祈使/陈述。
   - 雅：忠实基础上润色，北欧神话语境用词得当（如「诸神的黄昏」「诺恩三女神」），但**不过度文言、不堆砌辞藻**。
5. **Humanize 风格约束（v2 新增，引入 Humanize AI text 技能）**：
   - 输出须像人写的中文，**避免 AI 腔**：不滥用「仿佛」「宛如」「值得」「无疑」「可以说」「深刻」「见证」等空泛修饰；不堆砌四字成语；不强行排比三句；不滥用「——」。
   - 叙事块（briefings）允许文学性，但语气自然、口语化优先；任务/提示块保持短平快。
   - 具体禁用清单（节选自 Humanize AI text 技能 patterns）：delve/tapestry/landscape/pivotal/underscore/foster 等英文 AI 词无对应中文直译问题，重点是**不要生成对应中文腔**（如「深入探讨」「一幅……画卷」「至关重要」「凸显」「培养」的空泛堆叠）。
6. **换行不丢失（v3 强化，关键）**：项目基线行尾是 **纯 LF（不是 CRLF）**，所有 map_xml 必须保持纯 LF，禁止引入 CRLF 或混用。
   - **段落结构对齐**：德语原文每个"空行"是**段落分隔符**。中文翻译**必须保持相同段落数**——即德语 N 段，中文也 N 段，段间用空行（`\n\n`）分隔。
   - **⚠️ 易错点：段落被合并**。若中文把德语多个段落拼成一整段（常见诱因：用 ` / ` 连接、或顺手连写），空行位置就会丢失，自检会发现"段落数 ≠ 德语段落数"。**这不是机械插空行能修的**——必须回到语义，按德语段落边界把中文重新分段。机械插空行会因行号错位导致 cascading 错位。
   - 自检脚本（段落数对齐）：对 CHN 与 GER 的 `<text>` 内文分别按空行切段，要求段数相等。详见 §6 自检命令。
   - 多段故事块中，德语每个空行对应中文一个空行；段落数、空行数必须与源一致。
7. **不改动 GAME_\***：仅输出到 `GAME_CHN`。
8. **每次改动都提交 git**：单文件一提交（见 §1 流程）。

## 5. 执行流程（每个文件，v2：直接编辑 XML，去脚本化）

> **不再使用注入脚本**。直接用编辑器（Edit/Write）改 XML，按 `<string id>` / `<block id>` 精确替换 CHN 槽位。脚本是"多此一举"且易丢换行，故废弃 `tools/apply_map_xml_translation.py`。

1. **读取**：读目标 XML，列出全部 `(id, ger, eng)` 及 briefing 块。
2. **检索术语**：对照 `language_union.csv`，确定已知专有名词译法。
3. **翻译**：逐条 `ger → 简体中文`；剧情块保证通顺自然（Humanize 约束）；对齐 master 的文学性标准。
4. **直接编辑**：用 Edit 把 `<text lang="CHN" />` 改成 `<text lang="CHN">中文</text>`，或填充 briefing 内空白 `<text>`。**严格保留源文件换行、缩进、空行；行尾统一为 LF（项目基线即 LF，禁止引入 CRLF 或混用）**。
   - **正则/脚本操作铁律（v3 新增，来自 01_02 踩坑）**：任何自动化改 XML 都必须**作用域限定在 CHN `<lang code="CHN">` 内部**，绝不可让 `.*?` 跨 `</text>`/`<text>` 边界匹配（会污染 eng/ger）；也绝不可对 `<block id="...">`、`<lang>`、`<text>`、`<font>`、`<picture>` 外层标签做正则重建（会拆断标签）。只改 `<text>` 内层文本，外层标签一律原样保留。
5. **更新术语**：新增/修正术语追加进 `language_union.csv`（父仓库）。
6. **校验**：`grep -c '<text lang="CHN" />'` 应为 0（strings 段无残留空槽）；briefing 段 `<lang code="CHN"><text></text>` 应为 0。核对换行数与源一致。
7. **提交 git**：单文件一提交（子模块内），术语变更单独提交（父仓库）。

### 6.1 提交前自动自检（必跑，可脚本化）

在子模块目录 `GAME_CHN/` 内对目标文件跑（Python 示例）：

```python
import re, subprocess
p='map_xml/<file>.xml'
s=open(p,encoding='utf-8').read()
assert '\r' not in s, "CRLF 混入！"
blocks=re.findall(r'<block id="[^"]+">.*?</block>', s, re.S)
assert len(re.findall(r'<block $', s))==0, "block 标签被拆断"
assert len(re.findall(r'<font|<picture', s))==36, "font/picture 计数异常"
assert len(re.findall(r'<lang code="CHN">\s*<text>\s*</text>', s))==0, "存在空 CHN text"
# 段落数对齐（CHN vs GER），必须 0 mismatch
def count_paras(t):
    lines=[l for l in t.split('\n')]
    while lines and lines[0].strip()=='': lines.pop(0)
    while lines and lines[-1].strip()=='': lines.pop()
    paras=0; inp=False
    for l in lines:
        if l.strip()=='': inp=False
        elif not inp: paras+=1; inp=True
    return paras
mismatch=[]
for b in blocks:
    bid=re.search(r'<block id="([^"]+)"',b).group(1)
    cl=re.search(r'<lang code="CHN">(.*?)</lang>',b,re.S)
    gl=re.search(r'<lang code="ger">(.*?)</lang>',b,re.S)
    if not cl or not gl: continue
    ct=re.findall(r'<text>(.*?)</text>',cl.group(1),re.S)
    gt=re.findall(r'<text>(.*?)</text>',gl.group(1),re.S)
    if len(ct)!=len(gt): mismatch.append((bid,'count')); continue
    for c,g in zip(ct,gt):
        if count_paras(c)!=count_paras(g): mismatch.append((bid,'para'))
assert not mismatch, f"段落数不匹配: {mismatch}"
# eng/ger 必须 100% 等于干净基线提交（如 5db23ad 对 01_02）
```
要点：**段落数对齐**是 01_02 换行 bug 的抓因检查，每次必跑。

### 6.2 提交纪律（防止 CRLF 污染）

- 子模块 `core.autocrlf=true` 会在 `git checkout` 时把 LF 工作树转 CRLF。为彻底防护，**子模块已加 `.gitattributes` 强制 `*.xml eol=lf`**（提交 `0ad577a` 引入），勿删除。
- 提交子模块 XML 时用 `git -c core.autocrlf=false commit`，提交后用
  `git cat-file blob HEAD:<file> | grep -c $'\r'` 验证 blob 为纯 LF（应返回 0）。
- 若正则/脚本改坏文件：**立即 `git checkout <clean_commit> -- <file>` 回滚**，不要试图手工修补被拆断的标签。
