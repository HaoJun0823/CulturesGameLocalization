## 21:22 波兰语(POL)整合进 map_xml XML

目标：把波兰版游戏 `G:\Projects\Cultures_Saga_Remix\Bramy Asgardu\DataX\Libs\data\maps` 的波兰语合并进 `Localization/map_xml/*.xml`。

关键发现与流程：
- 波兰地图共 37 个含 map.dat；XML 共 128 个；按 map.dat 的 MD5 匹配，40 个 XML 命中波兰地图（33 个唯一 MD5，部分多人地图同一 MD5 对应多个 XML）。4 个 `demo_mainmenu_*` 无文本目录、无对应 XML；86 个 XML 无波兰对应（波兰版没有这些地图）。
- **波兰字符串是二进制 `strings.cif`，不是 `strings.ini`**；但本质就是 ini，需用 `Tools/Cultures-map-editor/supplements/initialization.py` 的 `decode()` 解码（gen2 起 cif=ini）。
- `decode()` 内部按 **cp1252** 解释字节；波兰语正确编码是 **cp1250**，必须 `raw.decode('cp1250')` 还原（否则 ł→³/ê 乱码）。`briefings.txt` 是明文，也按 cp1250 解码。
- 合并脚本 `Tools/integrate_pol_xml.py`：解码 cif→cp1250→写成 UTF-8 临时文件 → `StringsParser`/`BriefingsParser` 解析 → `parse_xml_file`/`write_xml_file` 合并进匹配 XML（先自动备份 map_xml）。已对 40 个 XML 整合，波兰字符验证正确。
- **坑**：loc_tools 的 `detect_encoding` 会优先选 cp1252，所以波兰文本不能直接让解析器读原始文件，必须经 cp1250 转 UTF-8 临时文件。loc_tools 没有 append 函数，合并需手写。

复用提示：日后集成其他语言版本（如 cz/ru）走同一流程，改 `LANG` 与源目录即可。

## 21:57 loc_tools.py base 复制块新增 .hlt 文本字符处理

需求：base 复制时 ger 的特殊字符必须处理（之前 hlt 只是字节原样拷贝，无字符修正）。

实现（仍在 `Tools/loc_tools.py`，v1.4 后续改动）：
- 新增模块级常量 `BASE_SCRIPT_TEXT_EXTS = {'.hlt','.ini','.txt','.cfg','.log','.lst','.script'}`。
- 新增辅助函数 `_copy_base_script_file(src,dst,base_encoding,target_encoding,apply_fix)` 与递归 `copy_base_scripts(...)`：
  - 文本型扩展名：读字节 → 按 base 编码解码（默认 windows-1252） → 若目标语言 `apply_fix_1251` 则 `fix_1251_chars` → 按目标 `encoding` 写回。
  - 二进制（如 .pcx，以及未在文本集合内的扩展名）：`shutil.copy2` 原样拷贝。文本处理异常时同样回退原样拷贝。
- base 复制块改用上述函数；`base_encoding` 取自 base 语言（ger）的 `lang_configs` 配置，`target_encoding` 取当前构建语言 `encoding`。
- 行为边界：`fix_1251` 仅在目标语言 `apply_fix_1251=True`（即 CHN/GB2312）时触发，把 ger 的 ä/ö/ü/ß 转 ASCII 以适配 GB2312；eng 等 `fix_1251=False` 时原文保留（字节无损）。
- 注意：`.fnt` 未列入文本集合（疑为二进制字体），保持原样拷贝；如日后确认 fnt 为文本需另加。
- 已通过单元自测（临时脚本 _t_base_copy.py，已删）：FIX 路径 ü→u/Ü→U/ß→ss/ö→o、子目录递归、pcx 字节一致；RAW 路径保留原字符。
